## Query and recovery properties

Primary pages fetch bounded rows on the server; they do not fetch thousands of records to paginate in React. Counts and rows use one PostgreSQL read snapshot, including end-page clamping. Each HTTP page is a fresh snapshot: concurrent insertion/removal can legitimately move an item between pages; this is not an immutable multi-request export snapshot. Ownership is part of the database predicate.

Scope compatibility repair no longer stops after 1,000 Programs. A parameterized SQL eligibility query finds only Programs with unmaterialized authoritative rules or unlinked explicit legacy hosts, in id-ordered batches of 100. Normal materialized inventories do not incur one repair transaction per Program. Repair retains the existing Program lock and backfill rules; discovery is never its source of authorization. The paged Target view retains stored-artifact compatibility conversion for legacy runs on that page only, outside the Program transaction.

Existing owner/Program/Target/time indexes and primary/unique keys serve the new bounded queries. No speculative index, schema migration or policy-version change was introduced. Recent selectors and immutable evidence samples intentionally remain capped context, not paginated collections. Compatibility response shape and per-user authorization remain intact. Boundary tests and the browser suite verify the supported navigation models; limits on native transport, production deployment and arbitrary-scale exports remain explicit.
