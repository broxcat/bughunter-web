# Black-box assessments

BugHunter currently supports only externally observable assessments:
Targets → Scope → Recon → Research Plan → Research → Findings → Report.
Authenticated Recon remains black-box runtime testing with explicitly authorized accounts. Anonymous, Account A, Account B and context differentials are retained. Discovery never expands Scope Assets, origin/path boundaries or exclusions.

New Programs and execution snapshots use BLACK_BOX. New Recon and Research sessions capture no authorized internal sources. New Research Plans use runtime evidence, with empty sourceSignals and sourceEvidenceRefs. Codex and Claude receive the same black-box instructions. assessment-policy.json remains a read-only compatibility file; it supplies no source locators or internal host authorization.

The experimental White-box selector, badges and source editor are retired. Former assessment/assessment-sources endpoints return 410 for authenticated clients. Migration `20261106090000_black_box_only` converts current Programs, deactivates sources, changes their default to inactive and prevents current configuration from re-enabling White-box or sources.

Historical enums, source records, Recon/Research/plan snapshots, Findings and Reports are retained. Historical WHITE_BOX means documentary metadata of a retired mode. A NULL mode remains Legacy / mode not captured. Historical snapshots are never reclassified as BLACK_BOX. Generating a new plan from an old Recon creates a black-box runtime plan without internal-source objectives.

Deploy the additive migration before restarting the shared web/worker image. No database reset, volume removal or research-console rebuild is needed: Research instructions and policy files are generated by the web backend. Existing historical sessions and files are preserved.
