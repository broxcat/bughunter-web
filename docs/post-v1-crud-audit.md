# Supported mutation audit through Milestone 2

The existing 67-handler inventory is the source index. There are 46 handlers with mutations, **54 actual mutating method entries**: 52 protected entries (including the HMAC worker) and two public authentication/account entries. Milestone 1 had 53 methods; Milestone 2 adds explicit asset replacement on an existing handler. No PUT, generic historical edit/delete or new lifecycle capability was invented.

The inventory-driven regression exercises anonymous admission for all 52 protected entries, explicit foreign Origin for the 51 browser-session entries, and malformed JSON/missing-resource handling for those 51. It preserves deliberate idempotent absent/private Program/console deletion (200), rather than incorrectly converting every absence to 404. These are 155 named tests (152 at the Milestone 1 checkpoint), not a claim of 152 distinct routes. State/ownership/concurrency coverage also comes from the real-SQL workflow suites below; this is layered API/service coverage, not a Cartesian test of every payload against every method.

## Reviewed state contracts and evidence

Common protected admission: anonymous API requests return JSON 401; explicit foreign browser Origin is 403 before parsing, writing or publishing. Legacy routes that lacked that guard were fixed (#17). Wrong-owner resources remain excluded in SQL or under the existing trusted owner-lock helper. A malformed or absent private ID is never used as a filesystem path or shell input. Authenticated retired modes return global 410 without an existence lookup. 422 remains limited to pre-existing validation/quota conventions. Unexpected storage/queue/provider unavailability is not a missing-resource assertion.

## Audit limits

This is a practical supported-workflow audit, not a proof against arbitrary database corruption, infinite datasets, every possible interleaving, or a formal accessibility/security certification. Native CLI/model inference, genuine Burp and production deployment are not acceptance steps for these read/navigation/admission changes. The unchanged publication/recovery infrastructure and previous native acceptance remain documented in the #8 section; this pass does not claim a fresh native image build or production restart. Unknown backend/storage exceptions are not silently treated as an ownership success.

## Milestone 2 compatibility and concurrency additions

Legacy host EDIT/REMOVE now retire any bound ScopeAsset under the same owned Program transaction, rather than leaving authoritative authorization active behind an inactive host flag. Their existing Target response and new-identity behavior remain intact. Duplicate replacement rolls back; post-commit native cleanup is outside SQL locks. The version-aware Settings form sends the published Program updatedAt token and cannot overwrite concurrent policy changes. No new generic historical mutation, schema column or migration was introduced. The matrix now stubs/restores its own synthetic AUTH_URL; CI uses one worker without changing test deadlines/assertions.
