# Milestone 1 functional accessibility acceptance

This is a functional pass over the existing 21-page inventory, not the Milestone 6 design refresh or a formal accessibility certification. `tests/e2e/accessibilityAcceptance.mjs` visits each inventory page in light/dark mode at 1280/390px (84 page/theme/viewport cases). Read-only, historical and redirect routes are exercised as they actually exist; they do not acquire new forms or mutations for this audit.

The real browser checks visible control labels/names, nested interactive elements, keyboard reachability and visible focus, document width and intentional scrolling for wide tables. Text contrast is calculated from computed foregrounds and layered backgrounds, using the normal/large-text thresholds. Disabled controls and xterm's hidden input are excluded where those checks do not apply. Native radio groups are one Tab stop and are tested with arrow keys; unchecked radios are not incorrectly required to be separate stops. Closed disclosure contents are excluded until visible.

`programCollectionNavigation.mjs` additionally opens the actual destructive Target dialog, checks native modal background exclusion, Escape, opener focus restoration, Space on Close, explicit confirmation and retained controlled state during a paused deletion. The paused response is synthetic and never invokes a real deletion. Actual final-row Program deletion is a separate disposable pagination case. Required-field submission uses native validation and its browser-provided message. Labelled Target creation controls, brand buttons, control boundaries and focus outlines receive actual light/dark computed contrast checks. Existing Target/auth/Research browser workflows exercise their real forms and errors; generated API errors retain their existing status semantics.

## Narrow fixes

- Shared native Dialog cleanup closes the modal and restores its connected opener. Escape delegates to controlled state; an in-flight action cannot silently dismiss its confirmation.
- Editable control boundaries use a distinct control token, retaining the existing decorative separators and visual system. The dark subtle-text token was raised from a measured 4.25:1 failing example to readable contrast. Existing red brand/status presentation is retained.
- Host log expansion, historical navigation and cancellation are sibling controls, rather than links/buttons nested inside a button. Expansion exposes its state and relationship.
- The persistent Research terminal keeps CLI Tab by default. Ctrl+Shift+M explicitly toggles browser Tab navigation; help is visible and associated with xterm's input for assistive technology. The default CLI behavior is tested again after switching back. Provider, approval, authentication, tmux persistence and backend authorization are unchanged. The wrapper avoids modifying the five diagnostics WIP files.

Research's terminal-launch response is deliberately intercepted with a synthetic 503 in this accessibility matrix, so visiting the page never launches a provider or persistent console. This verifies the web keyboard boundary, not fresh native PTY/model execution; the previous #8 native acceptance remains separately recorded. Status checks retain words/icons; no color-only status system was added. No production deployment, public scan, global visual redesign or Target/Scope redesign occurred.
